# 식사 기록

`/commit/meals`에서 아침·점심·저녁·간식별 기록을 작성합니다. 각 날짜·식사 구분에 한 기록을 저장하고, 그 안에 최대 40개의 음식을 담습니다. 날짜는 한국 시간대로 해석하며 미래 날짜에는 저장할 수 없습니다.

## 음식 검색과 직접 입력

- 음식 검색에서는 쉼표로 여러 이름을 입력해 결과를 확인한 뒤 한 번에 담을 수 있습니다. 기록은 1인분으로 시작하며 반 인분 등으로 바꿀 수 있습니다.
- [제공량 기준표](../apps/server/src/modules/meals/serving-references.json)에서 출처와 기준량을 확인한 항목은 1인분 kcal를 자동으로 계산합니다. 기준이 없는 음식은 이름과 인분만 저장할 수 있으며, 1인분 열량을 아는 경우 입력할 수 있습니다. 직접 입력 탭에도 같은 열량 칸을 제공합니다. 합계에는 열량을 계산할 수 있는 항목만 들어갑니다.
- API 배포 전에 대상 DB의 대기 중인 마이그레이션을 확인하고 승인된 환경에 `20261124000000_meal_records`를 적용합니다. `MealRecord`와 `UserSchool`을 추가합니다. [배포 절차](deployment.md#운영-마이그레이션과-최초-배포-순서)를 따릅니다.
- 공식 음식의 기준 파일은 [foods-final.json](../apps/server/src/modules/meals/foods-final.json)입니다. 웹의 `dev`와 `build` 명령은 원본과 제공량 기준표에서 콘텐츠 해시와 CDN용 JSON을 생성합니다. 웹·서버는 같은 리비전으로 빌드합니다. 해시가 다른 동안에는 새 카탈로그 항목 저장을 거부하므로 양쪽 배포 후 웹 목록을 새로고침합니다.
- 저장 시 공식 음식의 이름·에너지·기준량·출처를 복사합니다. 기존 항목의 섭취량을 수정하면 저장 당시 기준으로 다시 계산합니다.
- 최근·자주 기록한 음식은 최근 30일의 직접 입력 및 카탈로그 기록 기준입니다. 아침·점심·저녁 중 하나를 기록하면 식사 활동 한 항목을 완료합니다. 간식 단독 기록과 칼로리는 퀘스트 계산에 사용하지 않습니다.

음식 데이터 출처는 [식품영양성분 데이터베이스(K-FCDB)](https://various.foodsafetykorea.go.kr/nutrient/)입니다.

## 학교 급식 (별도 작업)

급식 탭은 준비 중 화면을 표시하며 학교 검색·등록·급식 조회를 호출하지 않습니다. 앞서 만든 NEIS 초안과 저장한 급식 스냅샷 형식은 별도 작업을 위해 보관합니다. 해당 작업에서 [NEIS 교육정보 개방 포털](https://open.neis.go.kr/)의 `NEIS_API_KEY` 설정과 실제 학교 등록 및 조회를 검증합니다.
